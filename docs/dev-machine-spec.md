## 1. 현재 사양

| 항목 | 값 |
|---|---|
| OS | Windows 11 64비트 |
| 언어 | 한국어 |
| CPU | Intel Core i5-8250U @ 1.60GHz — 4코어 8스레드, 기본 ~1.8GHz |
| RAM | **8GB** (8192MB) — *32GB로 변경 예정, 아래 2절 참조* |
| GPU | NVIDIA GeForce MX150 |
| VRAM (전용) | **약 2GB** (1968MB) |
| DirectX | 12 |

### 읽을 때 주의할 점

- **GPU "전체 메모리 근사값 6005MB"는 실제 VRAM이 아님.** 시스템 메모리 공유분이 합산된 수치다. 실제 전용 VRAM은 **약 2GB**이며, 그래픽 한계를 판단할 때는 이 2GB 기준으로 볼 것.
- **페이지 파일이 12.5GB 사용 중으로 잡혀 있었음.** 물리 메모리가 부족해 디스크로 밀려나고 있다는 신호. 현재 8GB 상태의 체감 성능 저하는 대부분 여기서 나온다.
- **i5-8250U는 15W 저전력 칩이고 섀시가 얇다.** 짧은 작업은 부스트가 붙지만, 몇 분 이상 지속되는 부하(컴파일, 빌드, 라이트맵 베이킹, 셰이더 컴파일)에서는 발열로 클럭이 기본값 근처까지 떨어진다. **"느리다"기보다 "오래 못 버틴다"**에 가깝다.

## 2. 메모리 업그레이드 (예정)

**현재 8GB → 32GB로 변경 예정.**

- 이 모델 계열은 SO-DIMM 슬롯 방식이며, 슬롯 2개 기준 최대 32GB(16GB × 2)까지 지원된다.
- 다만 변형 모델에 따라 **온보드 메모리 + 슬롯 1개** 구성인 경우가 있으므로, 구매 전 `작업 관리자 → 성능 → 메모리 → "사용된 슬롯"` 항목으로 실제 구성을 확인할 것.

### 업그레이드 후 달라지는 것

- RAM 압박으로 막혀 있던 항목 대부분이 해소된다 — 안드로이드 에뮬레이터, Docker 다중 컨테이너, 엔진 + IDE + 브라우저 동시 구동, 페이지 파일 의존.

### 업그레이드해도 **그대로인 것** (중요)

- **VRAM 2GB** — 교체 불가. 3D 그래픽의 실질적 천장은 업그레이드 후에도 동일하다.
- **CPU 지속 성능** — 15W 발열 스로틀링은 그대로. 빌드·컴파일·베이킹 시간은 크게 줄지 않는다.

> 즉, 32GB 업그레이드는 **"동시에 여러 개를 띄울 수 있느냐"** 를 해결하지, **"무거운 것 하나를 돌릴 수 있느냐"** 를 해결하지는 않는다.

## 3. 개발 가능 범위

판단 기준은 2단(가능/불가)이 아니라 **3단**으로 본다. 가운데 칸이 실제 작업 시간의 대부분을 차지한다.

### 제약 없음

- 웹 풀스택 — Flask, Django, FastAPI, React, Vue, Node.js, Spring
- 백엔드 / API 서버, DB (SQLite, PostgreSQL, MySQL)
- C / 시스템 프로그래밍, WSL2 리눅스 환경
- 데스크톱 앱 — Python(Qt/Tkinter), C# WPF/WinForms, Java
- 중소 규모 데이터 분석 (pandas, scikit-learn 계열)
- **2D 게임 전반** — Godot, Unity 2D. 픽셀아트, 퍼즐, 비주얼노벨, 로그라이크, 플랫포머
- **턴제 전략 / 시뮬레이션** — 프레임 예산이 빡빡하지 않은 장르라 스펙 압박이 거의 없음

### 되는데 느림 (← 실제로 가장 주의할 구간)

| 항목 | 병목 |
|---|---|
| Unity URP 중간 규모 3D | 라이트맵 베이킹 · 셰이더 컴파일 · 대량 에셋 임포트가 수십 분~수 시간. 씬 분할 필수, 베이킹은 취침 전 예약 |
| 안드로이드 빌드 | Gradle 빌드가 CPU 스로틀링에 직격 |
| 안드로이드 에뮬레이터 | 에뮬레이터 단독으로 RAM 2~4GB 점유. **8GB에서는 실기기 USB 디버깅으로 우회** (32GB 업그레이드 후 해소) |
| Electron, Docker 다중 컨테이너 | RAM (32GB 업그레이드 후 해소) |

### 현실적으로 불가

- **Unreal Engine 5** — Nanite/Lumen이 VRAM 8GB급을 전제로 함. 8GB RAM에서는 에디터 자체가 정상적으로 열리지 않음. **게임 엔진 선택 시 가장 먼저 걸러야 할 항목.**
- 오픈월드 / 대형 지형, 실시간 GI, 2K 이상 고해상도 텍스처 대량 사용, 대규모 물리·파티클, VR
- **iOS 네이티브** — macOS 필수. Flutter로 코드 작성은 가능하나 빌드·서명 불가
- **ML 모델 학습** — VRAM 2GB는 딥러닝 학습에 사실상 무의미. 토이 수준(MNIST급) 외에는 불가 → **Colab 등 클라우드 GPU로 이관**. 추론은 소형 모델만.

## 5. 문서 갱신 안내

**이 문서는 메모리 업그레이드 시점에 수정이 필요하다.**

KAL이 대화 중 **"메모리 업그레이드했다" / "32GB로 바꿨다"** 는 취지의 언급을 하면 — 이 대화창이든 다른 대화창이든 — 다음을 수행할 것:

1. 1절 표의 `RAM` 항목을 실제 설치 용량으로 수정하고, "*32GB로 변경 예정*" 주석 제거
2. 1절 "읽을 때 주의할 점"에서 페이지 파일 관련 항목 삭제 또는 갱신
3. 2절을 "업그레이드 예정"에서 "업그레이드 완료(날짜)"로 변경하되, **"업그레이드해도 그대로인 것"(VRAM 2GB · CPU 지속 성능)은 반드시 유지**
4. 3절 "되는데 느림" 표에서 RAM이 원인이던 항목(에뮬레이터, Electron/Docker)을 "제약 없음"으로 이동. **CPU·VRAM이 원인인 항목은 그대로 둘 것**
5. 상단 헤더의 사양 확인 시점 갱신

> 갱신 시 주의 — RAM 증설로 해소되는 것과 해소되지 않는 것을 섞지 말 것. VRAM 2GB와 15W CPU 제약은 이 노트북을 쓰는 한 영구적이다.
